## Naming

- Table: singular snake_case (`business_case`, `approval_task`). Avoid reserved words (`user` → `app_user`).
- Columns: snake_case, generated from camelCase properties.
- Booleans: `is_*` / `has_*` or a plain adjective (`active`).
- Foreign keys: `<relation>_id`, generated by `p.manyToOne(...)`.

## Required columns

Every entity spreads `baseProperties()` from `src/database/base-properties.ts`:
`id uuid PK`, `created_at`, `updated_at`, `created_by`, `updated_by` (user ids, set by the service), `version` (optimistic locking).

## Entity template

```ts
import { defineEntity, p } from '@mikro-orm/core';
import { baseProperties, WILDCARD_SCHEMA } from '../../database/base-properties.js';

export const THING_STATUSES = ['draft', 'submitted'] as const;

export const ThingSchema = defineEntity({
  name: 'Thing',
  tableName: 'thing',
  schema: WILDCARD_SCHEMA, // REQUIRED: keeps migrations schema-agnostic
  properties: {
    ...baseProperties(),
    title: p.string().length(200),
    status: p.enum(THING_STATUSES).default('draft'),
    owner: () => p.manyToOne(User),
  },
});
export class Thing extends ThingSchema.class {}
ThingSchema.setClass(Thing);
```

Then add the class to `ENTITIES` in `src/database/entities.ts` (there is no folder discovery).

## Types

| Data | Builder | Notes |
|---|---|---|
| Money | `p.decimal('string').precision(15).scale(2)` | Never float. Currency fixed to MYR; store `currency` only if multi-currency is approved |
| Dates with time | `p.datetime()` | Stored as `timestamptz`, UTC |
| Date only | `p.date()` | |
| Enum | `p.enum(CONST_ARRAY)` | Generates a check constraint |
| Free text | `p.text()` | Validate max length in the Zod schema |
| Flexible structure | `p.json<T>()` | Only when the shape is validated by Zod; prefer columns for anything reported on |

## Relationships

- Use `p.manyToOne(X)` with explicit `.nullable()` when optional. Default delete rule: restrict. Use `deleteRule('cascade')` only for owned children.
- Many-to-many with attributes: model the join table as its own entity.

## Row-level security (financial, contract, personal tables)

Defence in depth on top of service-level checks. In the migration (hand-edit after generation):

```sql
alter table "<table>" enable row level security;
alter table "<table>" force row level security;
create policy "<table>_visibility" on "<table>" using ( <predicate on current_setting('app.user_id', true)> );
```

Access these tables only inside `withDbUserContext(em, { userId }, ...)` (`src/database/db-user-context.ts`).

## Never do

- Hard-code a schema name anywhere (entities, SQL, migrations).
- Edit a migration that has been applied in any shared environment; add a new one.
- Drop or rename a column without the user's explicit approval (data loss).
- Store secrets or tokens in plain text: hash them (see `api-key` module).
