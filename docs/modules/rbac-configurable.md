# Configurable RBAC: which fixed rules become configurable

Status: **decided by the product owner, 2026-10-22; built 2026-10-23.** Inventory of the access rules fixed in code (on top of the 53 permission codes, whose role grants, data-access levels, scopes and approval rules were already configurable), and what each becomes.

## Become configurable (14)

| #   | Rule today (fixed in code)                                                                          | Becomes                                                                                                                                                                            | Default                                                                                                                                            |
| --- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Vendors never see financial, contract or personal data, whatever their role                         | **The role's data-access levels decide** for vendors too                                                                                                                           | The seeded Vendor role keeps `none` for all three                                                                                                  |
| 3   | TRM: a vendor with a company-wide role still sees only assigned applications (and their portfolios) | **The role's scope decides** (as for SAD)                                                                                                                                          | —                                                                                                                                                  |
| 4   | Vendors never edit TRM fields                                                                       | **The role decides** (`trm:application:update`)                                                                                                                                    | Vendor role has no edit                                                                                                                            |
| 5   | Vendors never place applications in domains                                                         | **The role decides** (`trm:domain:manage`)                                                                                                                                         | —                                                                                                                                                  |
| 7   | The EA roadmap is never shown to vendors                                                            | **The role decides** (`trm:roadmap:read`)                                                                                                                                          | Vendor role has no roadmap                                                                                                                         |
| 6   | Vendors never see the all-ServiceNow-fields panel                                                   | **New permission** "View all ServiceNow fields" (`trm:source-fields:read`)                                                                                                         | Every role that views TRM today, except Vendor                                                                                                     |
| 8   | Vendors can never search the staff directory                                                        | **New permission** "Search the staff directory" (`people:directory:read`)                                                                                                          | Every staff role                                                                                                                                   |
| 12  | Only a system administrator grants or removes the system administrator role                         | **New permission** "Grant the system administrator role" (`access:system-admin:manage`)                                                                                            | System admins only. Still never to yourself (rule 15) or to a vendor (rule 2)                                                                      |
| 13  | Only a system administrator (or the starter) cancels a SAD draft                                    | **New permission** "Cancel any SAD draft" (`sad:draft:manage`)                                                                                                                     | System admins only                                                                                                                                 |
| 18  | Only the submitter resubmits, cancels or answers questions on their approval                        | **New permission** "Act for submitters" (`approvals:instance:manage`), within the holder's scope                                                                                   | Nobody                                                                                                                                             |
| 21  | People manage only their own out-of-office delegations                                              | **New permission** "Manage others' delegations" (`approvals:any-delegation:manage`, page _Out of office for others_)                                                               | System admins only. Delegating to yourself stays impossible                                                                                        |
| 9   | Vendors cannot be out-of-office delegates or roadmap owners; people pickers show staff only         | **Role setting** "Can act for staff" (`role.canActForStaff`: who may be a delegate or a roadmap owner). Other pickers (approvers, SAD API owners) offer anyone in the directory    | Approver roles: Tech EXCO, Finance EXCO, ARB member, ARB chair, enterprise architect, solution architect, application manager, PMO, portfolio lead |
| 25  | Whether approvers see the financial data of what they approve is fixed per approval type in code    | **Setting per approval type** on the approval-rule screen (`approval_workflow_setting`)                                                                                            | Today's values (business case: on; SAD: off)                                                                                                       |
| 27  | Which fields are financial / contract / personal is fixed in code                                   | **Admin-maintained "Field classification" list** (audited; structured fields only, maintained with `access:field-class:manage`; classes financial, contract, personal or internal) | Today's classes: TRM costs and roadmap cost (financial); people's names, roadmap owner, SAD names, API owners (personal)                           |

Also new: "Search the staff directory" is now a permission (`people:directory:read`, rule 8) and SAD draft cancel by others is `sad:draft:manage` (rule 13); holders of "Act for submitters" (`approvals:instance:manage`) can also cancel a returned SAD approval together with its draft. Raw ServiceNow fields in the all-fields panel keep their name-based classes (costs financial, people personal).

## Stay fixed in code (13)

| #   | Rule                                                                                                                                                                                                                                                          |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2   | Vendors can never be system administrators                                                                                                                                                                                                                    |
| 10  | The system administrator holds every permission and cannot be limited. Its seeded role also has data access `all` for financial, contract and personal data (since 2026-10-28; before that it was `none`, so admins saw "Restricted")                         |
| 11  | The system administrator role cannot be edited                                                                                                                                                                                                                |
| 14  | Anti-escalation: you can only grant permissions and data access you hold                                                                                                                                                                                      |
| 15  | You cannot change your own role assignments (system administrators excepted)                                                                                                                                                                                  |
| 16  | Nobody can disable their own account, system administrators included. Disabling and enabling other accounts needs "Manage users" (`access:user:manage`). (Product owner, 2026-10-23: the planned "Disable own account" permission was dropped as not useful.) |
| 17  | A submitter never approves their own request                                                                                                                                                                                                                  |
| 19  | Only the person who started a TRM sync run continues, completes or abandons it                                                                                                                                                                                |
| 20  | The person who started a SAD draft can always cancel it                                                                                                                                                                                                       |
| 22  | You manage only your own API keys (revoking others' is already a permission)                                                                                                                                                                                  |
| 23  | The submitter and everyone on an approval chain always see that approval                                                                                                                                                                                      |
| 24  | Approvers see every section of the SAD version they approve                                                                                                                                                                                                   |
| 26  | Every signed-in user reads the department list and the SAD template                                                                                                                                                                                           |

Also fixed, by necessity: sign-in, SAML, token refresh, sign-out and the health probe work without a session; everyone sees their own identity and notifications.

## Consequences carried through (2026-10-23)

- The non-negotiable "vendors never see financial, contract or personal data" becomes "**by default**": update `.github/copilot-instructions.md`, the `rbac-approvals` skill and the security-review checklist.
- Rule 7 reverses the TRM part 3 decision "vendors never see the roadmap" (now the permission decides).
- Rule 18 also lets holders resubmit a returned SAD for its submitter.
- New permissions and the role setting need the Roles screen, migrations (seeding as above), and tests for vendor and non-vendor holders.
